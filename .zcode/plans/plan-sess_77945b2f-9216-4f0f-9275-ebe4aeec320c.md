## Fix: extraction phase records no app metrics

### Problem
`ExtractionPhase.run()` never times its executor, so `MetricKey.EXTRACTION` (defined at `pyqenc/metrics.py:103`) has zero call sites and the `"extraction"` row never appears in metrics.yaml — violating `.kiro/specs/metrics-two-tier/requirements.md:124` (Req 2.5). Regression introduced by commit `4d0433f` (mkvextract removal); never restored by the `0482a66` rewrite.

### Changes

1. **`pyqenc/phases/extraction.py` (~line 863)** — wrap the executor call in the phase's top-level timer, mirroring the pattern used by every other phase (e.g. `audio.py:219`):
   ```python
   with self._collector.time(MetricKey.EXTRACTION):
       result = self._execute_extraction(wanted_artifacts)
   ```
   The function-local `from pyqenc.metrics import MetricKey` already exists at line 806 in `run()`; reuse it (move it above both `with` blocks for cleanliness). Per spec Req 3.7 (requirements.md:189-191), extraction records **only** the top-level key — no dotted sub-keys (`extraction.video`, etc.) will be added.

   Early-return paths (memoized result, dependency short-circuit, dry-run, all-reused) stay untouched: they return before the executor and correctly record only `RECOVERY`, matching other phases' reuse semantics.

2. **`tests/test_metrics_integration.py` (lines 252-312)** — update `test_extraction_recorded_for_mkvextract_tracks`:
   - Fix the docstring (remove "EXTRACTION key is not separately timed"; state that both RECOVERY and EXTRACTION are timed).
   - Add assertion `MetricKey.EXTRACTION in time_keys_called` alongside the existing RECOVERY assertion.

3. **Optional doc touch-up**: `.kiro/specs/metrics-two-tier/design.md:384-385` still describes the extraction call-site as "mkvextract"; update the wording to reflect the current ffmpeg per-track executor (cosmetic, keeps the spec's call-site table accurate).

### Verification
- Run the extraction metrics tests: `python -m pytest tests/test_metrics_integration.py -k extraction -v`
- Run the full metrics suite: `python -m pytest tests/test_metrics.py tests/test_metrics_integration.py -v`
- Sanity-check end-to-end if practical: a real/dry pipeline run should now produce an `"extraction"` entry in metrics.yaml after artifacts are extracted.

### Notes
- No changes needed in `metrics.py` itself — the collector, flush cadence (every 3 recordings), and report builder already handle the key; it was simply never fed.
- Out of scope (separate pre-existing issues found during investigation, not touched here): optimization test-encodes land under `encoding.*` dotted keys instead of `optimization.*` because `ChunkEncoder` hardcodes the ENCODING prefix; `parallelism` field from design.md is unimplemented.
