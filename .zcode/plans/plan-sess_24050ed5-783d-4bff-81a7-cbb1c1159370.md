# pyqenc cleanup branch — staged, functionality-preserving shrink

**Goal:** ruff clean, pytest green, dead code gone, comments concise and current-state, cheap duplication deduplicated, worst tests reworked toward external behavior — with a full audit table of every decision. Nothing user-visible changes except the one crash bug we fix (Stage 7). Each stage is an isolated commit; ruff + pytest must pass before the next stage starts.

Covers TODO.md **§4** (ruff), **§43** (11 stale audio tests), **§58** (sprawl), test-quality half of **§5**. §57 (disowned functions) stays out of scope.

## How candidates are treated (important)

Every item listed below is an **evidence-backed candidate, not a mandate**. The executing agent decides at the edit site: verify the claim still holds (grep the symbol, read the context), weigh local factors (readability, call-site churn, legitimate uniformity value), then act. Items judged "keep" are recorded with their reason — a kept-with-reason row is as valuable as a deleted row. Guardrails that are NOT candidates: the locked decisions below, the protected-symbol list, and the stage gates.

## Deliverable: cleanup report

Maintained throughout, committed as `cleanup-report.md` at repo root (precedent: `code-stats.md`, `TODO.md`). One row per acted-on or explicitly-kept candidate:

| # | Item (symbol, file:line) | Category | What it was / why candidate | Action taken | Reason | Post-check |

Categories: dead-code / comment / import / inline / DRY / test / repair / config. Post-check column: how it was verified (grep-clean, ruff, pytest green, vulture silent, behavior unchanged). Summary totals at the bottom (lines removed per category, tests deleted/rewritten).

## Decisions locked in (from your answers)

1. **Comments**: short spec links OK; essays/task-notes/historical narration not. Comments state current key facts only.
2. **Dead code**: test-only references do NOT count as live → dead. **Exception: QualitySearch V1+V2 stay** (sanctioned — V3 will be reworked into V4 based on V2 hacking onto V1); trim their comment bloat, add one concise "kept as reference for planned V4 (TODO §51)" note.
3. **DRY**: cheap → refactor now; costly → log in TODO.md for later.
4. **Tests**: rework implementation-pinning tests toward external behavior. Good test = bug condition + observable property (unique/countable/round-trippable), not exact string formats or MagicMock spies on internals.
