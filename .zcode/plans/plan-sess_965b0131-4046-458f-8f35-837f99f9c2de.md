# Uniform phase run — template-method base class + contract enforcement

## Justification (what & why)
The phase-terminal-runner contract mandates one uniform run footprint (memo guard → skip check → deps → banner → timed recover under `recovery` → recovery line → dry-run / no-pending branches → timed work under the top-level phase key → typed result). That skeleton is hand-copied 8× today and has drifted: probe records zero metrics, job has no banner and partial timing, chunking/encoding time work outside run() with gaps, optimization reads dep results before resolving deps and misuses the RECOVERY key, merge's wanted filter is dead, and extraction's top-level key was missing entirely until a manual fix (0.14.2). A single concrete `run()` in a base class makes these bug classes structurally impossible — while status decisions stay with the concrete phases. Optimization is encoding on a chunk subset and follows the encoding contract via parameterization, not duplication (DRY).

## Step 1 — `PhaseBase` (new `pyqenc/phases/_base.py`, re-exported from phase.py)
One concrete `run(dry_run)` — footprint only, no status synthesis:
memo guard → `_skip_check()` (default None; reads config only, never dep results) → shared `_ensure_dependencies` (wraps `resolve_dependencies`; phase supplies typed `_dep_failed/_dep_pending` factories) → banner iff `BANNER` class flag (default True; once; skip/dep-failure emit none) → `_log_key_params()` hook → `with collector.time(RECOVERY): self._recover()` → `log_recovery_line` iff internal artifacts non-empty → wanted filter → dry-run branch → no-pending branch → `with time(self._metric_key): self._execute(wanted)` → cache on `self.result`.

Status semantics:
- `_recover() -> Recovery(artifacts_internal, pending)` is the single source of truth; raises `_RecoveryError` on fatal mismatch (chunking mode, encoding probe, job source mismatch without --force) → typed FAILED.
- Template never decides COMPLETED/FAILED: `_execute(wanted)` returns the typed result with the outcome the concrete phase chooses — contract: COMPLETED or FAILED only, never PENDING; the template's dry-run branch is the only PENDING producer.
- REUSED is purely mechanical: `not pending → _reused_result()` — a phase hook building the typed result (default via `_make_result(REUSED, ...)`; merge replays persisted summary; probe rebuilds from cached values). No `complete>0` clause — empty phases simply have no pending work.
- Dry-run default: PENDING iff pending else REUSED; Job overrides to readonly-execute (does read-only work, returns its result, only the write is skipped).

Invariants (docstrings):
- Completeness is presence-based only (file + sidecar presence; atomic writes mean a present file is never incomplete — no content peeking).
- Invalidation is a separate recover-time concern and MAY read persisted settings (chunking mode mismatch, encoding probe mismatch, audio chain signatures, probe manual-crop override, job source mismatch).
- `wanted` is derived from external input; phases never mutate it during recovery.
- Sidecars (job.yaml, probe.yaml, optimization.yaml state) are NOT artifacts: job/probe return empty artifact lists; their `pending` comes from recover's state-currency check (absent or invalidated), and the recovery line is skipped when the internal list is empty.

## Step 3 — Runner: hard assertion instead of coercion
Delete `_as_failed` (runner.py:324-344). PENDING-on-execute is a contract violation: log ERROR ("internal error: phase X returned PENDING on an execute run — this is a bug"), still flush + close the collector (debug evidence + always-unregister invariant), skip the finalize broadcast, then raise a dedicated `PhaseContractError`. The run fails loudly with a traceback.
